# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Используйте
[Private vulnerability reporting](https://github.com/iudanet/tg-llm-worker/security/advisories/new)
на вкладке Security — это приватный канал, видимый только мейнтейнеру.

Опишите: что не так, как воспроизвести, что получает атакующий. Ответ
постараюсь дать в течение недели.

## Модель угроз

Воркер обслуживает **закрытый список пользователей** (`CHAT_WHITE_LIST`)
и хранит их переписку. Опасность представляют:

- посторонний, получивший возможность слать боту апдейты — он тратит ваш
  ключ OpenAI и может испортить чужой контекст;
- утечка токена бота или ключа API — из логов, ответов, артефактов сборки;
- попадание в публичный репозиторий персональных данных: Telegram user id
  позволяет написать человеку в личку.

Не входит в модель: злоупотребления со стороны уже допущенного пользователя
(он и так имеет полный доступ к боту), и содержимое ответов языковой модели.

## Что делает воркер для защиты

- **`TELEGRAM_WEBHOOK_SECRET` обязателен.** Без него воркер не стартует:
  иначе `POST /webhook` принимал бы апдейты от кого угодно, а whitelist
  проверяет `from.id` из того же тела запроса, то есть был бы декоративным.
- Секреты сравниваются через `crypto.subtle.timingSafeEqual`.
- Служебные страницы `/` и `/init` закрыты тем же секретом, отдаются
  с `no-store`, `no-referrer`, `nosniff` и строгим CSP.
- Пустой `CHAT_WHITE_LIST` означает «никто», а не «все».
- В логи не попадают ни текст сообщений, ни картинки, ни расшифровки —
  только идентификаторы, размеры и коды ошибок. URL скачивания файла
  содержит токен бота и не логируется никогда.
- `OPENAI_API_BASE` обязан быть `https`: по http ключ ушёл бы в заголовке
  открытым текстом.
- История диалогов изолирована ключами `chat:<chat_id>[:<thread_id>]`.

## Что защищает репозиторий

- `pre-commit` с `gitleaks` блокирует токены, реальные user id, KV namespace
  id, локальные конфиги (`wrangler.toml`, `.dev.vars`, `.env`) и бинарники.
  Установка: `pre-commit install`.
- CI прогоняет линтер, типы, тесты, сборку, сканер секретов и `npm audit`.
- Релизный workflow проверяет артефакты на секреты перед публикацией.
- CodeQL и Dependabot — по расписанию.

## Если секрет всё же утёк

1. Перевыпустите: токен бота — через `/revoke` у @BotFather, ключ OpenAI —
   в дашборде, webhook-секрет — сгенерируйте новый (`openssl rand -hex 32`).
2. Обновите: `npx wrangler secret put <ИМЯ>`.
3. Заново привяжите webhook через `/init?token=<новый секрет>`.
4. Если секрет попал в git — переписывать историю недостаточно: считайте его
   скомпрометированным и меняйте.
